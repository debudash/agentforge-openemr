Week 2 demo · read aloud · about 4½ minutes

Co-Pilot Demo Script

Big text is what you say. Amber lines are what you do. Pause wherever you click; the answer can take a few seconds, and silence is fine.

0:00

Opening

Patient chart open, signed in as doctor1

This is the Clinical Co-Pilot, built into OpenEMR. The scenario: a physician is preparing a follow-up visit. The chart has structured data, but what's new is buried in a scanned lab report and an intake form the front desk just uploaded. The Co-Pilot reads those documents, cites every fact back to the page it came from, and brings in guideline evidence — kept separate from facts about the patient.

0:25

Upload

Demo Data tab → abnormal lab → Generate New Docs

First, the documents. This generates a lab report and an intake form for this patient and files them into the chart through OpenEMR's own upload call — the same path the Documents tab uses. As far as the Co-Pilot can tell, these are real uploads, and they arrive unread.

1:00

Extraction and citations

Co-Pilot tab → wait for "what changed"

When I open the Co-Pilot, the supervisor sees two unread documents and hands them to the intake extractor. A vision model reads each page into a strict schema, and then code — not the model — checks every value: the quote it cites has to be on the page it names. Here's what changed: potassium 5.4, eGFR 58, A1c 7.4.

Click a citation chip on one of the values

Every value is clickable. The page opens with the quote boxed, so I can see exactly where it came from. If the model had invented a value, it would be marked unsupported — never shown as a fact.

1:55

Evidence retrieval

Ask: What does guidance say about high potassium with an ACE inhibitor?

Now a question that needs guidance. The supervisor routes it to the evidence retriever: keyword and vector search over a small guideline corpus, then a reranker. The guideline passages come back in their own section, each cited to its source. The patient's potassium is cited to the lab. Guidance is never turned into advice for this patient.

Open "How this was answered"

And here's how it got there — the handoff, and the tools it ran. Nothing about the routing is hidden.

2:45

A refusal

Demo Data → another patient's report → Generate → back to Co-Pilot

What if the wrong report lands in this chart? This one names a different patient. The Co-Pilot reads it, sees the name doesn't match, and refuses to file it. Nothing from it reaches the chart, and the refusal is shown — not silently skipped.

3:15

The eval gate

Terminal: .venv\Scripts\python -m evals.stage2.gate

Quality is enforced, not hoped for. This is the eval gate: seventy-six cases, five pass-or-fail rubrics — schema valid, citation present, factually consistent, safe refusal, and no patient data in the logs. It needs no model and no network, so it runs on every push and every merge request.

Switch to merge request !3

And it does block regressions. This merge request removed three lines from the citation check. The gate caught it, the pipeline failed, and the merge was blocked.

3:55

Observability

Copy the trace id under an answer → LangSmith → window B: CopilotHealth

Every answer carries a trace. In LangSmith I can see the tool sequence, latency for each step, and the tokens used. And the health view shows the service's own counters — latency, document reads, failures — with no patient data anywhere in the logs.

4:25

The dashboard (optional)

Open another patient → the new dashboard fills the chart → click Edit on Allergies

One more thing. The patient dashboard itself was ported from PHP to React, reading OpenEMR's FHIR API. It opens right in the chart for the patient you clicked, with no second login, and Edit uses OpenEMR's own editors.

4:45

Close

That's the Week 2 Co-Pilot: it reads messy clinical documents, cites every fact to its source, keeps guidance apart from the patient, refuses what doesn't belong — and a gate stops any change that breaks that.
