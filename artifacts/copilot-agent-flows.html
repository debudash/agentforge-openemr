Opening the panel

What happens between clicking the CopilotAgent tab and the rounding list being ready?

What to read off it

  • Scope is checked three times on this path alone — roundingList intersects appointments with the panel, ChartReader asserts again per patient, and SessionStore.open re-checks on the far side of the trust boundary.
  • The rounding list is an intersection, not a lookup. An appointment booked with you is not enough; the patient must also be assigned to you. Otherwise scheduling staff could grant chart access by booking.
  • Prefetch is fire-and-forget. The open response returns immediately with everything queued; the browser polls for readiness. Work the clinician may never use is paid for up front to make selection instant.

Reading one chart

How does a broken data source become an honest answer instead of a silent omission?

What to read off it

  • The empty / error split is the safety-critical part. Collapse them and a failed allergy read becomes an empty list, which the model renders as "no known allergies" — a negative clinical finding invented out of an exception. The doctor then prescribes penicillin.
  • Failures are recorded, not raised. That is what makes the partial state possible downstream: the response can say which source failed instead of quietly leaving it out.
  • Only the exception class is logged, never its message — messages carry SQL fragments, paths and sometimes patient data.

Topic check

Why does asking about the weather no longer replay the previous answer?

What to read off it

  • Two earlier fixes failed. An off_topic flag plus a prompt rule lost against a conversation full of helpful clinical answers; turn-scoped citations stopped the leak but the re-lookup then re-fetched allergies. Only removing the context settled it.
  • It fails open, and that is correct — this is a convenience filter with verification and scope standing behind it. Contrast assertInScope, which fails closed because nothing stands behind it.
  • A question about a different patient passes this check on purpose. It has to reach the scope layer to produce access_denied and a scope_denied audit event — a probe must not dissolve into a polite brush-off.

The tool loop

What stops a confused model from looping forever, inventing tools, or widening its own scope?

What to read off it

  • A tool never throws at the model. Invented names, corrupted arguments and scope denials all come back as JSON results, so a weak model can correct itself on the next round instead of ending the turn.
  • returned_ids is filled here and spent in flow 5. Every record a tool hands over is recorded, and only those ids can support a claim this turn.
  • The cap is a cost control as well as a safety one — five rounds bounds the worst-case spend of a single question to roughly 1.7× the measured mean.

Claim verification

What does the system do when the model writes something true-sounding that no record supports?

What to read off it

  • Turn-scoped citation is the anti-regurgitation rule. Memory carries the answer text but never the citation ids, so a restated answer has nothing valid to cite and every claim in it dies.
  • Numbers are checked against the cited record, not merely against the chart. A plausible-looking potassium value that appears nowhere in the record it cites is removed.
  • The re-lookup forces a tool call on its first round. A model that answered from memory once is not trusted to choose to look things up when merely asked.

Choosing a state

How does everything that happened collapse into one honest label?

complete
Everything in scope was retrieved and every claim verified. A correct refusal of an off-topic question lands here too — declining properly is a success.
partial
Something is qualified: a source failed, the loop ran out, a rule could not be evaluated, or claims were removed. The reasons are shown, not hidden.
unable_to_answer
The machinery failed, or nothing survived verification. This is the state that should make somebody investigate.
access_denied
Not permitted. Carries no patient content and no hint whether the patient exists, so it cannot be used to enumerate ids.

What to read off it

  • "Complete" is a statement about evidence, not satisfaction. It means nothing was silently dropped — which is why an off-topic refusal qualifies and a rate-limited answer does not.
  • Every qualifying reason is accumulated, then reported together rather than the first one winning, so a clinician sees all of what was wrong.
  • Removing claims but keeping none is treated as failure, not as a thin answer. An answer whose every sentence was deleted is not a partial answer.

Switching patients

What guarantees one patient's conversation can never colour another's answer?

What to read off it

  • Two mechanisms, same failure. Clearing history removes A's text from memory; turn-scoped citations mean that even if remembered text resurfaced it could not cite anything and would be deleted.
  • Asking about a panel patient who is not active is refused, which collapses the reachable surface to one chart at a time.
  • The cost is real: a clinician cannot keep two threads alive and flip between them. The demo chose the obviously-correct version over the more useful one.

Recurring idioms

fail closed
Authorization checks deny when they cannot run. assertInScope throws rather than returning false, so a caller who forgets to test the result still reads nothing.
fail open
Convenience checks allow when they cannot run. The topic check earns this only because verification and scope stand behind it. A control with no backstop never fails open.
correlation id
One id minted per request in api.php, threaded through OpenEMR's audit log, the agent's event stream and the LangSmith trace, so one question can be reconstructed across three systems.
structured error
Tools answer with {"result": "error", ...} rather than raising, so the model gets something it can act on and the attempt stays visible in the trace.
the model proposes
Every clinical flag comes from a versioned rule engine the model cannot invoke, suppress or soften, and every sentence it writes must cite a record fetched in the same turn.
